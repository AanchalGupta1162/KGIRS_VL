Information retrieval is the task of finding documents in a large collection that satisfy a user's information need. A user expresses that need as a query, usually a few keywords, and the system returns a ranked list of documents it judges most relevant. Unlike a database lookup, retrieval deals with unstructured text where there is no single exact answer, so systems estimate relevance and order the results by score. Classic applications include library catalogues, web search engines, enterprise search, and legal or patent search.
An inverted index is the core data structure behind fast text search. For every term in the vocabulary it stores a postings list: the identifiers of the documents that contain the term, often with term frequencies and word positions. To answer a query, the search engine looks up the postings list of each query term and merges them, so only documents containing at least one query term are ever scored. Building the index involves tokenization, normalization, stop-word removal and optionally stemming, and the index is compressed to save memory and disk space.
TF-IDF weighting scores a term in a document by multiplying its term frequency by its inverse document frequency. Term frequency rewards terms that occur often in the document, while inverse document frequency, the logarithm of the number of documents divided by the document frequency, rewards terms that are rare across the collection. A term that appears in only a few documents therefore receives a high weight in those documents, while a term found in nearly every document receives a weight close to zero. Documents and queries become TF-IDF vectors that are compared with cosine similarity for ranking.
BM25 is a probabilistic ranking function that improves on plain TF-IDF. It adds term frequency saturation, so the tenth occurrence of a term adds much less to the score than the first, and document length normalization, so long documents are not favoured simply for containing more words. Two parameters control this behaviour: k1 sets how quickly term frequency saturates and b sets how strongly scores are normalized by document length. BM25 remains a strong baseline for document ranking and is the default scoring function in search engines such as Elasticsearch and Lucene.
Retrieval systems are evaluated by comparing their ranked results with relevance judgments made by people. Precision is the fraction of retrieved documents that are relevant, and recall is the fraction of relevant documents that were retrieved. Because users rarely look past the first page, measures such as precision at k, mean average precision and normalized discounted cumulative gain focus on the top of the ranking. Test collections such as those built for the TREC evaluation campaigns provide queries, documents and judgments so that different ranking methods can be compared fairly.
Query expansion adds related terms to a user's query to address vocabulary mismatch, the problem that relevant documents may use different words than the query. Expansion terms can come from a thesaurus, from word embeddings, or from relevance feedback. In pseudo relevance feedback the system assumes the top ranked documents are relevant, extracts their most informative terms and runs the expanded query again. The Rocchio algorithm formalizes this by moving the query vector toward relevant documents and away from non-relevant ones, which often improves recall at some cost to precision.
Web search engines combine several components: a crawler that downloads pages by following links, an indexer that builds an inverted index over billions of documents, and a ranker that orders the results for each query. Beyond text matching, web ranking uses link analysis. PageRank treats the web as a graph of pages and hyperlinks and gives a page a high score when many important pages link to it. Modern engines also use click logs, freshness and hundreds of other signals, often combined with learning to rank models.
Text preprocessing decides which terms a retrieval system actually indexes. Tokenization splits text into words, case folding lowercases them, and stop-word removal discards very common words such as the, of and and. Stemming reduces words to a common root, so connecting, connected and connection all match the query term connect; the Porter stemmer is the classic algorithm. Lemmatization does the same with dictionary forms. These choices change the vocabulary, the document frequencies and therefore every TF-IDF weight in the collection.
A knowledge graph represents facts as a network of entities and the relationships between them. Each fact is a triple of subject, predicate and object, for example Marie Curie, won, Nobel Prize in Physics. Entities are nodes and relationships are labelled edges, so the graph can be traversed to answer questions that combine several facts. Large public knowledge graphs include Wikidata and DBpedia, and many companies build their own to power search, recommendations and question answering.
The Resource Description Framework, RDF, is the W3C standard for publishing knowledge graphs on the web. Every entity and relationship is identified by a URI, and facts are stored as subject, predicate, object triples in a triple store. SPARQL is the query language for RDF: a query describes a graph pattern with variables, and the engine returns every set of bindings that matches the pattern in the graph. SPARQL supports filters, optional patterns, aggregation and federated queries across several endpoints.
An ontology defines the vocabulary of a knowledge graph: the classes of entities, the properties that connect them and the rules they must follow. For example, an ontology can state that every Professor is a Person and that the teaches property links a Person to a Course. Ontologies are written in languages such as RDF Schema and OWL, and a reasoner can use them to infer new facts that were never stated explicitly. A shared ontology lets different organisations integrate their data consistently.
Entity linking connects mentions of names in text to the matching entities in a knowledge graph. The word Jaguar in a sentence might refer to the animal, the car manufacturer or a sports team, so the linker uses the surrounding context and the popularity of each candidate entity to choose the right one. Entity linking follows named entity recognition in many pipelines and is a key step in building knowledge graphs automatically from documents, as well as in semantic search where queries are mapped to entities.
Knowledge graph embeddings represent entities and relations as vectors in a continuous space so that facts can be scored numerically. In the TransE model a relation acts as a translation, so the vector of the head entity plus the relation vector should lie close to the vector of the tail entity. Models such as DistMult, ComplEx and RotatE capture more complex relation patterns. The learned embeddings are used for link prediction, entity similarity and as features for other machine learning models.
Real knowledge graphs are incomplete: many true facts are simply missing. Knowledge graph completion, also called link prediction, predicts missing edges such as the birthplace of a person or the genre of a film. Methods range from rule mining, which learns patterns like people usually share the nationality of their birthplace, to embedding models and graph neural networks that score every candidate triple. Predictions are evaluated with ranking measures such as mean reciprocal rank and hits at ten.
Wikidata is a free, collaboratively edited knowledge graph maintained by the Wikimedia Foundation. It contains more than one hundred million items, each with a unique identifier such as Q42, and statements that link items through properties. Statements can carry qualifiers and references that record when a fact was true and where it came from. Wikidata supplies structured data to Wikipedia infoboxes and can be queried by anyone through its public SPARQL endpoint.
Search engines use knowledge graphs to answer questions directly instead of only returning documents. When a user searches for the height of the Eiffel Tower, the engine recognises the entity, looks up the height property in its knowledge graph and shows the answer in a knowledge panel. Question answering over knowledge graphs translates a natural language question into a structured graph query, which gives precise answers but only for facts that the graph contains.
Word embeddings represent each word as a dense vector learned from large amounts of text, so that words used in similar contexts receive similar vectors. Word2vec learns them by predicting a word from its neighbours or the neighbours from the word, and GloVe factorises a global word co-occurrence matrix. Unlike sparse TF-IDF vectors, embeddings capture meaning: car and automobile end up close together even though they share no characters, which makes embeddings useful for semantic similarity and query expansion.
The transformer is a neural network architecture built on self-attention, in which every word in a sequence computes a weighted combination of all the other words. Because attention is computed in parallel rather than word by word, transformers train efficiently on very large text collections. Models such as BERT are pretrained to predict masked words and then fine-tuned for tasks like classification and question answering, while GPT models are trained to predict the next word and generate text.
Text classification assigns documents to predefined categories such as spam or not spam, positive or negative, or a topic label. A classic approach represents each document as a TF-IDF vector and trains a linear model such as logistic regression, naive Bayes or a support vector machine. These models are fast and surprisingly strong baselines. Fine-tuned transformer models usually achieve higher accuracy but need more computation. Performance is measured with accuracy, precision, recall and the F1 score on a held-out test set.
Named entity recognition finds spans of text that name people, organisations, locations, dates and other entity types. It is usually framed as sequence labelling, where every token receives a tag such as B-PER for the beginning of a person name or O for outside any entity. Conditional random fields and bidirectional LSTMs were standard models before transformers. Named entity recognition is the first step of information extraction pipelines that populate knowledge graphs from text.
A language model assigns probabilities to sequences of words. Early n-gram models estimated the probability of the next word from counts of the previous few words, with smoothing to handle unseen combinations. Neural language models replaced counts with learned representations, and large language models with billions of parameters trained on web-scale text can now write fluent text, translate, summarise and answer questions. They can also produce confident but incorrect statements, known as hallucinations.
Topic modelling discovers the themes that run through a collection of documents without any labels. Latent Dirichlet Allocation assumes that each document is a mixture of topics and each topic is a probability distribution over words, and it infers both from word co-occurrence. A topic about sport might give high probability to match, team and goal. Topic models help researchers explore large archives, summarise collections and provide low-dimensional document features.
Sentiment analysis determines whether a piece of text expresses a positive, negative or neutral opinion. Businesses apply it to product reviews, social media posts and customer support tickets to track how people feel about a brand. Lexicon methods count positive and negative words, while supervised machine learning models learn from labelled examples and handle negation and sarcasm better. Aspect based sentiment analysis goes further and identifies the opinion about each feature, such as the battery or the screen of a phone.
Supervised machine learning fits a model to labelled training data by minimising a loss function, typically with gradient descent. A model that memorises the training data but performs poorly on new examples is overfitting. Practitioners hold out a validation set to tune hyperparameters and a separate test set to report final performance, and they use regularisation, dropout and early stopping to improve generalisation. Cross validation gives a more reliable estimate when labelled data is scarce.
A relational database stores data in tables of rows and columns, where each table describes one kind of entity and keys link related rows across tables. SQL, the Structured Query Language, is used to define tables and to insert, update and query data. A query such as SELECT name FROM students WHERE year = 3 declares what result is wanted, and the database decides how to compute it. Normalisation organises tables to avoid redundant data and update anomalies.
A database index speeds up queries by avoiding a full scan of the table. The most common structure is the B-tree, a balanced tree that keeps keys sorted so that a lookup, an insertion or a range query takes logarithmic time. Hash indexes support fast equality lookups but not range queries. Indexes use extra storage and slow down writes, because every insert and update must also modify the index, so database designers index only the columns that queries filter or join on.
Graph databases such as Neo4j store data as nodes and relationships rather than tables. Each node and relationship can carry properties, and relationships are stored as direct pointers, so moving from a node to its neighbours takes constant time regardless of the size of the graph. Neo4j is queried with Cypher, a pattern matching language in which MATCH (p:Person)-[:FRIEND_OF]->(f) RETURN f finds the friends of every person. Graph databases suit social networks, fraud detection, recommendation and knowledge graph applications.
A transaction groups several database operations into one unit of work. The ACID properties guarantee correctness: atomicity means all operations succeed or none do, consistency means the database moves from one valid state to another, isolation means concurrent transactions do not interfere, and durability means committed changes survive crashes. Databases implement these guarantees with write-ahead logging, locking and multiversion concurrency control. A bank transfer that debits one account and credits another is the textbook example.
NoSQL databases relax the relational model to scale across many machines or to store data that does not fit neatly into tables. Key-value stores such as Redis map keys to values, document databases such as MongoDB store flexible JSON documents, wide-column stores such as Cassandra handle very high write volumes, and graph databases store connected data. Many NoSQL systems trade strict consistency for availability and partition tolerance, a trade-off described by the CAP theorem.
The query optimizer turns a declarative SQL query into an efficient execution plan. It considers different join orders, join algorithms such as nested loop join, hash join and merge join, and whether to use an index or scan the whole table. A cost model estimates the work of each plan from table statistics such as row counts and value distributions, and the optimizer chooses the cheapest plan. A poor plan can make a query run thousands of times slower, which is why the EXPLAIN command is essential for tuning.
A data warehouse collects data from many operational systems into one store designed for analysis rather than transactions. Extract, transform and load pipelines clean and integrate the data, which is typically organised in a star schema with a central fact table of measurements surrounded by dimension tables such as time, product and region. Columnar storage and pre-computed aggregates make analytical queries over millions of rows fast, and business intelligence tools build reports and dashboards on top.
Many databases include full-text search so that applications can search text columns without running a separate search engine. PostgreSQL converts text into a tsvector of normalised lexemes, stores it in an inverted GIN index and ranks matches with functions such as ts_rank that consider term frequency and proximity. MySQL and SQLite offer similar features. Dedicated engines such as Elasticsearch still provide more advanced relevance ranking, faceting and scalability for large document collections.
Dense retrieval encodes queries and documents into embedding vectors with a neural network and ranks documents by the similarity of their vectors. Dual encoder models such as DPR are trained on pairs of questions and relevant passages so that matching pairs end up close together. Because it compares meaning rather than exact words, dense retrieval can find relevant documents that share no terms with the query, overcoming the vocabulary mismatch problem of sparse TF-IDF and BM25 retrieval.
Vector databases store millions of embedding vectors and answer nearest neighbour queries quickly. Exact search would compare the query with every stored vector, so they use approximate nearest neighbour indexes such as HNSW, a navigable graph of vectors, or IVF, which clusters the vectors and searches only the closest clusters. Systems such as FAISS, Milvus and pgvector trade a small loss in recall for search that is orders of magnitude faster, which makes semantic search practical at scale.
Retrieval augmented generation combines a retriever with a large language model. For each question the retriever finds relevant passages from a document collection, and the passages are inserted into the prompt so the language model can ground its answer in them. This reduces hallucinations, lets the model use private or recent information without retraining, and allows answers to cite their sources. The quality of the final answer depends heavily on the quality of the retrieval step.
Hybrid search combines sparse keyword retrieval with dense semantic retrieval. Keyword methods such as BM25 excel at exact matches like product codes, names and rare technical terms, while dense embeddings capture paraphrases and synonyms. A hybrid system runs both retrievers and merges the ranked lists, commonly with reciprocal rank fusion, which scores each document by the sum of one divided by its rank in each list. Hybrid retrieval is often more robust than either method alone.
Many search systems rank in two stages. A fast first-stage retriever such as BM25 or a dual encoder selects a few hundred candidate documents, and a slower but more accurate reranker reorders them. Cross encoder rerankers feed the query and a document together into a transformer, letting every query word attend to every document word, and output a relevance score. Reranking the top candidates typically improves precision at the top of the ranking, measured by nDCG or mean reciprocal rank.
Before long documents are indexed for semantic search or retrieval augmented generation, they are split into chunks, because embedding models accept limited input length and a single vector cannot summarise a whole book. Chunks may follow fixed token counts with some overlap, or natural boundaries such as paragraphs and sections. Chunks that are too small lose context, while chunks that are too large mix several topics and dilute the embedding, so chunk size is an important tuning parameter.
Knowledge graphs and large language models complement each other. Language models are fluent but can hallucinate facts, while knowledge graphs store verified facts but are hard to query in natural language. GraphRAG and similar approaches retrieve entities and relationships from a knowledge graph and give them to the language model as context, and language models in turn help build knowledge graphs by extracting entities and relations from text. The combination supports explainable question answering over connected data.
The history of information retrieval spans more than seventy years. In the 1950s Hans Peter Luhn at IBM proposed using word frequency to identify the significant words of a document, an idea that underlies term frequency weighting. In the 1960s and 1970s Gerard Salton and his group at Cornell built the SMART retrieval system, introduced the vector space model and experimented with term weighting, relevance feedback and automatic indexing. Karen Sparck Jones showed in 1972 that rare terms discriminate between documents better than common ones, which gave rise to inverse document frequency. Stephen Robertson and colleagues developed the probabilistic model of retrieval, which led to the BM25 ranking function in the 1990s. The Text REtrieval Conference, TREC, began in 1992 and gave researchers large shared test collections and relevance judgments for systematic evaluation. The growth of the web brought new challenges of scale, spam and link structure, answered by crawlers, distributed inverted indexes and link analysis algorithms such as PageRank. Learning to rank methods then combined hundreds of relevance signals with machine learning. Since 2018 pretrained transformer models have changed the field again: neural rerankers, dense retrieval and retrieval augmented generation now sit alongside the classic methods, yet TF-IDF and BM25 remain strong baselines and are still used in the first stage of many modern search pipelines.
Recommender systems suggest items such as films, products, songs or articles that a user is likely to enjoy. Collaborative filtering makes predictions from the behaviour of many users: if two users rated many films similarly, a film liked by one is recommended to the other. Matrix factorisation, popularised by the Netflix Prize competition, represents users and items as latent factor vectors whose dot product predicts a rating. Content based filtering instead compares item descriptions with a profile of what the user liked before, often using TF-IDF vectors of the item text and cosine similarity, which works even for new items that have no ratings yet. Hybrid recommenders combine both approaches. Modern systems use deep learning, sequence models over a user's recent interactions, and graph neural networks over the bipartite graph of users and items. Recommendation is usually framed as a ranking problem, so offline evaluation relies on ranking measures such as precision at k, recall at k and nDCG, while online A/B tests measure clicks, watch time and purchases. Practical systems must also handle the cold start problem for new users and items, popularity bias that keeps recommending the same well-known items, and the need for diversity and serendipity so that users discover something new instead of near duplicates of what they already know.
